# DBA COF benchmark: dba-cof-1

This directory packages the historical electron closed-orbit finder (COF)
fixture. The common ring geometry and linear optics are described in the
[LaTeX note](../TeX/main.tex), Section 2. This README retains the electron-specific
solver configuration, run instructions, acceptance criteria and provenance.

The directory can be copied outside the OPALX checkout. All lattice definitions,
analysis scripts and reference data are included; no field maps, distribution
files, sibling sandbox directories or Git checkout are required. The external
requirements are an OPALX executable supporting `COF` and Python 3.10 or newer
with NumPy and pandas. The executable's normal runtime libraries must be available.

## Ring and solver settings

| Quantity | Value |
|---|---|
| Particle | Electron, approximately 250 MeV kinetic energy |
| Reference momentum `PC` | 0.2505104781131461 GeV/c |
| Fields | Hard edge; bend `HGAP=0`, `FINT=0` |
| Space charge / RF | None / none |
| COF integrator / time step | DOP853 / 5 ps |
| Maximum steps / path | 20,000 / 35 m |
| Finite-difference displacement | 30 micrometres; matching slope perturbation 3e-5 |
| COF Jacobian | Centered finite differences |

`cof.in` defines the complete ring and executes `ic: COF`, then `QUIT`.
`NALLOC=1` supplies a reference beam; COF follows single-particle trial orbits
for Newton iterations and finite differences. There is no `TRACK` run or
macroparticle distribution. This fixture retains DOP853; it is not the separate
Boris COF-versus-device-tracking comparison.
The retained `LINEARTRANSFERMAP*` options configure the separate element-map
builder, disabled in this input; they do not set the COF Jacobian calculation.

## Run both benchmark cases

From this directory:

```sh
OPALX_BINARY=/absolute/path/to/opalx \
OPALX_PYTHON=/absolute/path/to/python3 \
RUN_NAME=my-validation ./run.sh
```

If `opalx` and a suitable `python3` are already on `PATH`, just use `./run.sh`.
For the local OPALX Python environment, set `OPALX_PYTHON="$HOME/.venv-h6/bin/python"`.
Install Python dependencies in the environment you intend to use if necessary:

```sh
python3 -m pip install -r requirements.txt
```

The runner launches OPALX directly as one MPI process and sets one OpenMP thread.
Do not launch several copies of `run.sh` through MPI. For a cluster, execute the
wrapper inside the appropriate allocation with the executable's runtime modules
loaded.

Every run uses a fresh `results/<RUN_NAME>/` directory; an existing name is
rejected. With no name supplied, the wrapper chooses a UTC timestamp. It creates:

- `analytic/`: regenerated exact maps, working-point scan and summary.
- `opalx/nominal/`: the zero-seed input, COF output, log and comparison.
- `opalx/displaced/`: the displaced-seed input, COF output, log and comparison.
- `opalx/summary.csv` and `summary.json`: both case results.
- `opalx/provenance.json`: executable/input/reference hashes and Python versions.

The displaced seed is `x=y=0.1 mm`, `px=py=0.001` in normalized mechanical
momentum units. Each successful COF produces `closed-orbit.json`; the runner also
writes the map converted to slope coordinates and its difference from the
analytic map. A failed run returns a nonzero exit status and retains its logs.

To run only the input, copy it into a fresh directory and invoke OPALX there:

```sh
mkdir -p results
mkdir results/nominal-only
cp cof.in results/nominal-only/
cd results/nominal-only
OMP_NUM_THREADS=1 /absolute/path/to/opalx --info 1 cof.in
```

## Analytic model and acceptance criteria

`analysis/generate_analytic.py` regenerates the checked-in references using
the formulation in the [LaTeX note](../TeX/main.tex), Section 2.2. Its one-family
scan selects the stable working point near principal fractional phases (0.23, 0.31):

- Horizontal principal phase: **0.229892430867**.
- Vertical principal phase: **0.310463602980**.

These values are folded eigenphases, `min(Q mod 1, 1 - Q mod 1)`; they do not
specify the integer tune or select an oriented phase branch. The checked-in
`reference/` files are generated by this model and can be regenerated separately:

```sh
python3 analysis/generate_analytic.py --output results/analytic-only
python3 -m unittest discover -s analysis -p 'test_*.py' -v
```

The COF matrix uses `(x, px, y, py)`, with positions in metres and momenta in
`p/(m_e c)`. The analytic transverse block uses `(x, x', y, y')`. Using the actual
reference momentum `p0` reported by OPALX, the checker applies
`M_slope = T^-1 M_COF T`, where `T=diag(1,p0,1,p0)`.

The original benchmark's acceptance bounds are retained:

1. COF stability classification is `STABLE`.
2. Every entry of the transverse 4x4 slope map differs from the analytic value
   by less than `1e-6`, using metres for position coordinates (equivalently a
   1 m position scale for the dimensionless entrywise comparison).
3. Each closure-residual component has magnitude below `1e-7`: metres for `x,y`,
   dimensionless `p/(m_e c)` for `px,py`.

Energy drift and orbit coordinates are recorded, but have no additional
pass/fail threshold. The analytic files contain 6x6 maps; this runner checks
only the transverse 4x4 block. It does not independently test spectral tunes,
dispersion, the longitudinal map, finite fringes, space charge, or multi-turn
device tracking. This packaging does not change the original numerical bounds.

## Contents and provenance

- `cof.in`: complete OPALX input.
- `run.sh`: portable runner with configurable executable and Python paths.
- `analysis/`: analytic generator, COF comparison and analytic unit tests.
- `reference/`: independently generated maps, scan and expected phases.
- `requirements.txt`: Python dependencies.
- `CHECKSUMS.sha256`: hashes of the package files, excluding generated runs.

Packaged from the PR #553 / issue #544 fixture
`sandbox/Regression-Tests/dba-ring-cof-1`. The input and analytic equations are
preserved. Historical run files are not copied or presented as fresh results.

## Packaging validation

On 2026-10-19, the package was copied into a temporary directory outside the
checkout and run from an unrelated working directory. Both cases passed with
one MPI rank and one OpenMP thread:

| Seed | Result | Maximum transverse map error | Maximum position closure error | Maximum momentum closure error |
|---|---|---:|---:|---:|
| Nominal | PASS, STABLE | 6.31214e-9 | 2.16321e-13 m | 3.28103e-11 |
| Displaced | PASS, STABLE | 4.42278e-9 | 4.50864e-13 m | 2.60244e-11 |

Momentum errors use `p/(m_e c)`. The two analytic unit tests also passed.
The existing OpenMP executable reported revision
`c2f6aa0910fe8492182dc68ce78daf62c69159c3`; it was not rebuilt for this packaging
task. Fresh logs, per-case comparisons and provenance are retained in
`results/packaging-validation/`, with the combined results in
[`opalx/summary.json`](results/packaging-validation/opalx/summary.json).
